# 國立金門大學資訊工程學系 系統程式 (System Programming) 期末總結報告

## 前言：從高階應用到系統底層的探索之旅
本學期的「系統程式」課程，是一趟拆解計算機科學黑盒子的深度之旅。過去的程式設計課程多聚焦於演算法與應用層面的邏輯開發，而這門課則帶領我們向下深掘，探究程式碼是如何與作業系統（OS）、硬體資源進行高效且安全的互動。

透過一系列紮實的理論學習與四個維度（行程控制、檔案 I/O、並行同步、編譯器與虛擬機）的實作專案，我的學習軌跡跨越了使用者模式（User Mode）與核心模式（Kernel Mode）的藩籬。本期末報告將統整這學期的核心專案與學習筆記，展現我如何將抽象的系統理論轉化為具體可執行的程式碼。

---

## 第一部分：行程控制與作業系統介面 (Process Control & OS API)

在深入複雜的系統架構前，掌握行程的生命週期是系統程式設計的基石。

### 1. 行程控制的兩大核心機制
* **`fork()` 系統呼叫：** 學習了 OS 如何透過複製父行程的狀態（包含檔案描述子、暫存器狀態等）來建立子行程。我深刻理解了父子行程間「程式碼共用，但記憶體空間與變數完全獨立」的隔離特性。
* **`execvp()` 與 Fork-Exec 模式：** 理解了 `execvp` 如何進行「換腦手術」，將當前行程的記憶體清空並載入全新程式。實務上，我學會了利用父行程 `fork` 出子行程執行外部指令，並透過 `wait()` / `waitpid()` 讓父行程休眠等待，從根本上避免殭屍行程（Zombie Process）的產生。

### 2. 系統層級實戰：Mini-Shell 命令列直譯器 (期中專案)
我使用 C++ 開發了一個輕量級的 Shell，完整重現了命令列介面的底層運作：
* 完美整合了 Fork-Exec 模式，解析使用者輸入並載入外部程式（如 `ls -l`）。
* 深刻體會「行程狀態隔離」的概念：子行程的環境變數或目錄切換無法影響父行程，因此必須在 Shell 父行程內部直接呼叫 `chdir()` 系統呼叫，成功實作出內建指令 `cd`。

## 第二部分：檔案 I/O 與重導向技術 (File I/O & Redirection)

* **檔案描述符 (File Descriptor, FD)：** 掌握了 Linux 中「一切皆檔案」的核心概念（包含一般檔案、目錄、Socket 甚至是硬體設備）。透過 `open`, `read`, `write`, `close` 等底層系統呼叫，搭配 Buffer 緩衝區設計，實作了高效的資料搬運機制。
* **狸貓換太子的魔法 `dup2`：** 深入剖析了終端機重導向 (`>`) 與管線 (`|`) 的底層原理。透過 `dup2(fd, 1)`，成功將標準輸出（stdout）的指標強制轉向自定義的檔案描述符。
* **應用實作 (Ping Pong Tracker)：** 開發 Python 命令列工具，將程式記憶體中的動態狀態（勝負統計），透過 File I/O 機制安全地寫入本地端 JSON 檔案，實現資料持久化 (Data Persistence)。

---

## 第三部分：多執行緒與並行控制實戰 (Concurrency & Synchronization)

現代作業系統中，執行緒（Thread）具備極高的建立與切換效率，但共享記憶體區段的特性，也帶來了嚴峻的資源競爭挑戰。

* **銀行存提款模擬 (Race Condition 與 Mutex)：** 了解到高階語言的一行指令（如 `balance++`）在 CPU 底層會被拆解為 Read-Modify-Write。若發生 Context Switch，便會導致「更新遺失」。我透過 C++11 的 `std::lock_guard` 搭配 `std::mutex` 保護臨界區段（Critical Section），確保了資料的絕對一致性。
* **生產者與消費者問題 (Condition Variable)：** 為了避免忙碌等待（Busy Waiting）造成的 CPU 資源浪費，我實作了 `std::unique_lock` 與 `std::condition_variable`。透過 `wait()` 讓執行緒主動讓出 CPU 進入休眠，並利用 `notify_all()` 進行非同步喚醒，完美解決了執行緒間的步調協調。
* **哲學家用餐問題 (Deadlock 防範)：** 針對 Coffman 四大條件中的「持有並等待」與「循環等待」，我採用了 `std::lock` 的原子鎖定（Atomic Locking）演算法，保證多個資源要麼同時取得，要麼同時放棄，成功破壞死結的發生條件。

## 第四部分：編譯器與虛擬機底層實作 (Compiler & Virtual Machine)

了解了程式如何被 OS 執行後，最後一塊拼圖是理解「程式碼本身是如何被解析與轉譯的」。

### 1. 微型程式語言「Nova」編譯器開發
* 從零建立了一條完整的編譯管線（Pipeline）。
* 實作詞法分析器（Lexer）將字元流轉為 Token，並採用遞迴下降解析（Recursive Descent Parsing）建構出抽象語法樹（AST）。
* 採用 Visitor 模式走訪 AST 節點，將高階的樹狀結構扁平化，編譯成自定義虛擬機可懂的堆疊機中間碼（Bytecode）。

### 2. p0 Compiler 與 VM 底層機制解析
* **控制流跳躍：** 在編譯器中加入 `while` 迴圈支援。精準利用**回填技術 (Backpatching)** 解決了條件跳脫指令 (`JMP_F`) 在解析當下目標位址未知的難題。
* **函數呼叫機制 (Function Call)：** 深入解析虛擬機的堆疊幀（Stack Frame）記憶體管理。從 Caller 端的參數推入與返回地址記錄，到 Callee 端的區域變數綁定與作用域隔離。這徹底打通了我對程式遞迴（Recursion）如何在實體記憶體中展開與收斂的理解。

## 期末總結與深度反思

這學期的「系統程式」是一場極具挑戰性、卻又令人大呼過癮的硬核技術洗禮。回顧這幾個月的學習與實作，我的成長主要體現在以下三個層次：

### 1. 思維的降維打擊：從「理所當然」到「深究本質」
在過去的開發經驗中，開啟檔案、建立陣列、或是呼叫一個 Function，對我來說都是理所當然的「一行程式碼」。然而，這學期的課程無情地打破了這種黑盒思維。
當我親手追蹤 p0 VM 中的 Stack Pointer 偏移，我才真正「看見」了區域變數是如何在記憶體中誕生與消亡；當我在銀行帳戶模擬中遭遇非預期的餘額錯誤，我才深刻體會到 CPU 底層組合語言 Read-Modify-Write 交錯執行的殺傷力。系統程式迫使我放下對高階語法的依賴，改以 CPU 暫存器、記憶體區塊、以及 OS 排程器的視角來審視每一段程式碼。這種思維的轉換，讓我未來在面對效能瓶頸或潛在的 Memory Leak時，具備了更敏銳的直覺。

### 2. 除錯能力的淬鍊與環境掌控
系統層級的開發，往往伴隨著最令人崩潰的錯誤訊息：Segmentation Fault、Deadlock 或是 Zombie Process。
在開發 Mini-Shell 與編譯器的過程中，我遇到了無數次指標越界與記憶體隔離的坑。例如在實作 `cd` 指令時，我一開始誤讓子行程去執行，導致路徑永遠切換失敗。這些血淋淋的除錯過程，逼迫我熟練掌握了跨環境（Linux/WSL）的建置、檔案描述符狀態的追蹤，以及進階系統呼叫的錯誤捕捉（`perror`）。我學會了不再盲目猜測錯誤，而是有系統地透過 Log 和底層邏輯去定位問題。

### 3. 人機協作的現代軟體工程實踐
值得一提的是，在這次的期中 Mini-Shell 專案以及期末的觀念釐清中，我大量採用了與生成式 AI（Gemini）協作的開發模式。AI 扮演了極佳的「知識引導者」與「Code Reviewer」，幫助我快速搭建 Makefile、驗證 C++11 `std::lock_guard` 的語法細節，並釐清晦澀的 OS 概念。但我同時也體認到，在系統底層開發中，AI 產生的程式碼若未經開發者本人對記憶體與執行緒時序的嚴格檢視，極易引發災難性的系統崩潰。這份「主導架構、善用工具、嚴謹驗證」的經驗，是我這學期極為珍貴的收穫。

**結語：**
從最高層的高階語言語法解析（Nova Compiler），到中間的虛擬機執行環境（Stack Frame），再到作業系統的行程排程與 I/O 溝通（Shell & File I/O），最後直達最底層的 CPU 執行緒競爭與同步（Mutex & Condition Variable）。這四個維度的知識與實作，在我的腦海中串聯成了一幅完整且立體的「計算機系統全景圖」。

這門課賦予我的，不僅幾是撰寫 C/C++ 系統呼叫的技能，更是身為一位資訊工程學系學生，對系統架構的敬畏之心與掌控能力。我相信，這份紮實的底層內功，將成為我未來在大型軟體架構、雲端分散式系統或是高效能運算領域中，最堅不可摧的基石。
