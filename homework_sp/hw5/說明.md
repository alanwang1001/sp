# 系統程式核心概念說明報告

## 1. Thread (執行緒)
執行緒是作業系統能夠進行運算排程的最小單位。它被包含在行程（Process）之中，是行程中的實際運作單位。一個行程可以併發多個執行緒，每個執行緒執行不同的任務。

* **記憶體與資源共享**：同一行程內的執行緒共享該行程的記憶體空間（如全域變數、程式碼區段、除堆疊外的資料空間）與系統資源（如開啟的檔案、訊號等）。
* **獨立資源**：每個執行緒擁有自己獨立的暫存器（Registers）、程式計數器（Program Counter, PC）與堆疊（Stack），用以記錄各自的執行狀態與區域變數。
* **優勢**：建立與切換執行緒的成本（Context Switch Overhead）遠比建立行程低，且因為共享記憶體，執行緒間的通訊（IPC）不需透過作業系統核心，速度極快。

## 2. Race Condition (競爭條件)
當兩個或多個執行緒同時存取並嘗試修改同一個共享資源（如變數或檔案），且最終的執行結果取決於這些執行緒執行的精確時序（Timing）或交錯順序時，這種現象稱為競爭條件。

* **根本原因**：高階語言的一行指令（如 `counter++`）在 CPU 底層通常會被拆解為多個機器指令（Read-Modify-Write）：
  1. **Read**：將記憶體中的值讀入 CPU 暫存器。
  2. **Modify**：在暫存器中將值加 1。
  3. **Write**：將暫存器的結果寫回記憶體。
  若執行緒在步驟 1 與步驟 3 之間被作業系統排程中斷（Context Switch），另一個執行緒也進來執行相同操作，就會導致其中一個執行緒的更新被覆蓋，造成更新遺失（Lost Update）。
* **影響**：程式會表現出不可預期、隨機且難以重現的錯誤。

## 3. Mutex (互斥鎖，Mutual Exclusion)
為了防止 Race Condition 發生，必須確保任意時刻只有一個執行緒能進入存取共享資源的程式碼區域，這個區域被稱為**臨界區段（Critical Section）**。Mutex 就是實現互斥的最基本同步工具。

* **運作機制**：
  * **Lock（上鎖）**：執行緒在進入臨界區段前，必須先嘗試獲取 Mutex。如果該鎖已被其他執行緒佔用，目前執行緒會被阻塞（Blocked）或進入休眠，直到鎖被釋放。
  * **Unlock（解鎖）**：當執行緒完成對共享資源的存取並離開臨界區段時，必須釋放 Mutex，以便作業系統喚醒其他正在等待該鎖的執行緒。
* **代價**：過度使用 Mutex 會降低程式的併發效能，將多執行緒的並行運作演變成序列化（Serialized）執行。

## 4. Deadlock (死結)
死結是指兩個或多個執行緒在執行過程中，因爭奪資源而造成的一種互相等待的僵局。在沒有外力介入（如作業系統強制終止）的情況下，這些執行緒都將永遠卡死，無法繼續推進。

* **死結發生的四個必要條件（Coffman 條件）**：
  1. **互斥 (Mutual Exclusion)**：資源一次只能被一個執行緒使用。
  2. **持有並等待 (Hold and Wait)**：執行緒已經持有了至少一個資源，但又提出新的資源請求，而該資源正被其他執行緒持有，此時該執行緒保持等待，且不釋放已持有的資源。
  3. **不可搶佔 (No Preemption)**：執行緒已獲得的資源在未使用完之前，不能被其他執行緒強行奪走，只能由持有者自願釋放。
  4. **循環等待 (Circular Wait)**：存在一個執行緒的封閉環鏈，每個執行緒都在等待下一個執行緒所持有的資源（例如：T1 等待 T2 的資源，T2 等待 T1 的資源）。
* **預防與避免**：破壞上述四個條件中的任意一個即可避免死結。常見方法包括固定資源獲取順序、使用超時鎖（Timeout Lock）或同時獲取所有需要的資源。
