# p0 Compiler: `while` 迴圈實作與函數呼叫機制解析

本文件詳細說明如何在 p0 編譯器中實作 `while` 迴圈語法，並解析編譯器內建的函數呼叫機制。

---

## 一、`while` 迴圈的設計原理與實作

要在 p0 compiler 中支援 `while` 迴圈，必須修改編譯器的三個階段：詞法分析 (Lexer)、語法解析 (Parser) 以及虛擬機 (VM)。

### 1. 詞法分析 (Lexer) 的修改
在將字元流 (Stream of characters) 轉換為標記 (Tokens) 的階段，必須讓編譯器認識 `while` 這個關鍵字。
* **做法**：在 `TokenType` 列舉中加入 `TK_WHILE`，並在 `next_token()` 的識別碼判斷中新增 `strcmp(cur_token.text, "while") == 0`，將其分類為 `TK_WHILE`。

### 2. 語法解析 (Parser) 的修改
`while` 迴圈的核心挑戰在於**控制流 (Control Flow)** 的跳躍。我們利用四元組產生以下邏輯：
1. **標記迴圈起點 (`loop_start`)**：在準備解析條件式前，記錄目前的指令地址 (`quad_count`)，因為迴圈本體執行完畢後需要跳回這裡重新判斷。
2. **條件跳脫 (`JMP_F`)**：解析條件式後產生 `JMP_F` (Jump False) 指令。如果條件為 0 (False)，就必須跳出迴圈。但因為此時還不知道迴圈的結束位址，我們利用**回填技術 (Backpatching)**，先填入 `?` 並記錄此指令的索引 (`jmp_f_idx`)。
3. **無條件折返 (`JMP`)**：解析完迴圈主體 (Body) 後，產生一個無條件跳躍指令 `JMP`，目標地址為步驟 1 記錄的 `loop_start`。
4. **回填結束地址**：將現在的 `quad_count`（即迴圈外第一行指令的地址）回填給步驟 2 的 `JMP_F` 指令。

### 3. 虛擬機 (VM) 的修改
原本的 VM 只有條件跳躍 `JMP_F`，需要新增對應無條件跳躍 `JMP` 的支援。
* **做法**：新增 `else if (strcmp(q.op, "JMP") == 0)` 條件，處理邏輯為 `pc = atoi(q.arg1) - 1;`。減 1 的原因是 VM 迴圈的結尾會執行 `pc++`，這樣下一輪迴圈才會剛好落在正確的目標地址。

## 二、p0 Compiler 函數呼叫機制解析

p0 compiler 使用**堆疊幀 (Stack Frame)** 來模擬真實 CPU 的函數呼叫與變數作用域 (Scope)。以下為其四個核心執行階段：

### 1. 預先掃描 (Pre-scanning)
在 VM 開始執行前，會先掃描所有中介碼，記錄所有 `FUNC_BEG` 的函數名稱與對應的 PC 進入點，建立類似「函數地址對照表」的結構。

### 2. 呼叫端準備 (Caller 端)
當遇到如 `add(1, 2)` 的函數呼叫時：
* **`PARAM` 指令**：將參數值計算完畢並依序推入共用的參數暫存區 (`param_stack`)。
* **`CALL` 指令**：
  * 開闢新的堆疊幀 (`sp++`)，確保新函數有自己獨立的變數空間。
  * 記錄返回資訊：包含返回地址 (`ret_pc`) 以及準備接收回傳值的變數名稱 (`ret_var`)。
  * 將 `param_stack` 中的參數值搬移到新幀的傳入參數區 (`incoming_args`)。
  * 將 PC 跳轉至目標函數的進入點。

### 3. 接收端執行 (Callee 端)
* **`FORMAL` 指令**：將 `incoming_args` 裡的參數值，綁定為該函數內的「區域變數」。
* **區域變數隔離**：VM 中的 `get_var()` 與 `set_var()` 函數**永遠只對當前的堆疊幀 (`stack[sp]`) 進行讀寫**。這確保了不同函數（即使有同名變數）互不干擾，同時也是支援遞迴 (Recursion) 的關鍵機制。

### 4. 回傳與銷毀 (Return 階段)
當函數執行到結束或 `return` 時：
* **`RET_VAL` 指令**：
  * 取得要回傳的運算結果。
  * **銷毀堆疊幀 (`sp--`)**：將控制權與變數空間退回前一個函數。
  * 將回傳值寫入 Caller 先前指定的接收變數。
  * 將 PC 設回當初記錄的 `ret_address`，程式便能接續在 `CALL` 之後繼續執行。
